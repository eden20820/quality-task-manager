# Online form signature workflow

- Archive tabs are disjoint: regular contains signed, legacy non-pending and manually archived forms; pending contains explicit pending-signature and legacy adhesion forms.
- Reopening a form carries its archive ID into Save. PDF/DOCX generation and upload must succeed before the original record is removed. Deletion matches original category, path and description, and must return a removed row. If replacement loses a concurrent race or deletion fails, the new copy is rolled back and the API reports failure instead of claiming completion with an old pending copy left behind. Old storage cleanup is best-effort only after the old record was removed.
- This uses existing session-scoped INSERT/DELETE privileges and organization/storage RLS. No service-role client, new grants or migrations are required. It is compensating multi-step replacement, not a cross-storage/database transaction; unexpected rollback failures are logged for cleanup.
- `archived` means explicitly moved without completing signatures, never signed. The move copies the exact bytes, changes archive metadata, and does not synthesize a signature or send email. Later unsigned edits preserve this state; completing the signatures changes it to signed.
- Notifications are centralized in archive creation: only a **new pending record** sends to both existing Caeli quality recipients (eden@caeli.pro and sergey@caeli.pro). Replacements, completed forms and manual moves skip notification. Caeli recipients are gated by the record's organization ID; other organizations' content is never sent to them.
- Sender is the existing Brevo configuration. API responses distinguish sent (provider acceptance), partial, failed and skipped. Provider acceptance is not proof of inbox delivery. Tests mock the provider and do not send real mail. No historical production records or delivery logs were audited by local tests.
- Shelf forms preserve existing automatic signatures by default, but allow leaving either signature empty. Missing signature cells survive DOCX reopening. Save and Download both carry the source archive ID, preventing a second initial notification when completing a pending shelf form.
- Development PDFs use a centered 19pt David title, 12pt body and centered 475pt tables. Paired fields, inline checks, side-by-side deviation/status panels and compact row padding fit a standard one-product/three-measurement form including both signatures on one A4 page. Long entries or extra rows continue rather than clipping or shrinking text. Other forms retain their original spacing and widths.

Verification: full Vitest suite, webpack production build/TypeScript, real renderer round trips, archive rollback/concurrency checks, exact-recipient/organization notification tests and rendered PDF/DOCX inspection. Live browser QA remains limited by managed Next.js preview incompatibility; inbox delivery must be checked in production.
